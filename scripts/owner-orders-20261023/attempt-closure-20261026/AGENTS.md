- Abandoning an idempotency key requires a durable server closure written under the create's b2b_idem lock and checked by the canonical create; absence, timeout or client locks never release a key — prevents late-arrival duplicates.
- Closures are immutable and keyed by partner+key, independent of the closer's current authorization; rollback is containment that keeps the create guard, and full removal requires zero closures — prevents reopening closed keys.
- The closure RPC reuses the create's actor scope/role/partner guards before the lock and reveals nothing on denial; frontend consumes it only via useCloseOrderAttempt on an explicit user click (never on timeout), fenced before/after, and only a schema-valid `closed` in the same current scope releases a new key — prevents probing, blind key release and stale responses.
- Rollout never assumes CREATE OR REPLACE drains in-flight calls: a SECURITY DEFINER trigger on the idempotency write path takes the same b2b_idem lock and refuses closed keys; authorization is re-run after every b2b_idem wait; candidate/rollbacks carry bounded lock/statement timeouts — prevents old-body duplicates, stale-auth reveals and indefinite waits.
